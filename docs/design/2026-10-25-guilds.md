# Design: ระบบกิลด์ (MVP, ไม่มีเรื่องเงิน)

สถานะ: ร่างเพื่อให้โดมตัดสินใจ ยังไม่มีโค้ดหรือ migration · 25 ต.ค. 2569

## ทำไม

ตอนนี้ห้องก๊วนมีอยู่แค่คืนเดียว พอหมดเวลาจองห้องก็ปิด คนที่มาเล่นด้วยกันประจำไม่มีที่รวมตัว
ไม่มีอะไรสะสมให้รู้สึกว่า "กลุ่มเราโตขึ้น" กิลด์คือกลุ่มถาวรที่อยู่ข้ามหลายคืน มีชื่อ มีตรา
มีเลเวล และมีอันดับเทียบกับกลุ่มอื่น เพื่อให้คนอยากกลับมาเล่นที่ร้านบ่อยขึ้นแบบเดียวกับเกมออนไลน์

ของที่ใช้ต่อยอดได้ทันที:

- ห้องก๊วน (`party_rooms`, `party_members`) ที่ทุกห้องผูกกับการจองสนามที่จ่ายแล้ว
- แต้ม Elo ติดตัวผู้เล่น (`player_ratings`) และสถิติรายคืน (`party_player_stats`)
- ตารางอันดับผู้เล่นแบบไม่เปิดเผยบัญชี (`player_ranking_board` + `profiles.public_player_id`)
- ระบบรายงานและดูแลเนื้อหาของคอมมูนิตี้ (`community_reports`, `/admin/community`)
- แบบแผน "ตารางสาธารณะห้ามมี user id" ตั้งแต่ migration 0020

## สรุปสิ่งที่เสนอ

- ผู้เล่นที่ล็อกอินแล้ว **สร้างกิลด์ได้ฟรี** ตั้งชื่อ ชื่อย่อ (แท็ก) เลือกตราจากชุดที่ร้านเตรียมไว้ และเขียนคำอธิบายสั้น ๆ
- **หนึ่งคนอยู่ได้หนึ่งกิลด์** ในเวลาเดียวกัน มีตำแหน่ง หัวหน้า / รองหัวหน้า / สมาชิก
- เข้ากิลด์ได้ 3 แบบตามที่หัวหน้าเลือก: เปิดรับทุกคน / ต้องขออนุมัติ / ต้องมีรหัสเชิญ
- กิลด์ได้ **XP** จากการเล่นจริงของสมาชิกที่ร้าน แล้วขึ้น **เลเวล**
- **ซีซั่นรายเดือน** มีตารางอันดับกิลด์ จบซีซั่นแล้ว 3 อันดับแรกได้ **เหรียญรางวัล** ติดหน้ากิลด์ถาวร
- ห้องก๊วนติด **ป้ายกิลด์** ได้ หน้ากิลด์แสดงคืนก๊วนที่กำลังจะมาถึงของกิลด์
- **ไม่มีเงินเกี่ยวข้องเลย** ไม่หารค่าสนาม ไม่มีเหรียญแลกส่วนลด ไม่แตะราคา การจอง หรือการตรวจสลิป

## ผู้เล่นเห็นอะไร

| หน้า | ใครเห็น | มีอะไร |
|---|---|---|
| `/guilds` | คนที่ล็อกอิน | รายชื่อกิลด์ ค้นหาชื่อ และตารางอันดับ 3 แท็บ: XP ซีซั่นนี้ · เลเวล · ฝีมือ |
| `/guilds/[id]` | คนที่ล็อกอิน | ตรา ชื่อ แท็ก เลเวลพร้อมแถบ XP สมาชิกและตำแหน่ง เหรียญรางวัล XP ล่าสุด คืนก๊วนที่กำลังจะมา ปุ่มเข้าร่วม/ขอเข้าร่วม |
| `/guilds/new` | คนที่ล็อกอินและยังไม่มีกิลด์ | ฟอร์มสร้างกิลด์ |
| `/me` | เจ้าของบัญชี | การ์ด "กิลด์ของฉัน" ลิงก์ไปหน้ากิลด์ และปุ่มออกจากกิลด์ |
| `/admin/guilds` | แอดมิน | รายชื่อกิลด์ รายงานที่เข้ามา เปลี่ยนชื่อ/ซ่อน/ยุบกิลด์ สวิตช์เปิด-ปิดการสร้างกิลด์ |

หน้าอันดับกิลด์ให้เห็นเฉพาะคนที่ล็อกอิน เหมือนตารางอันดับผู้เล่นตอนนี้

### หัวหน้าทำอะไรได้

- แก้คำอธิบาย ตรา และวิธีรับสมาชิก · ดูและสร้างรหัสเชิญใหม่
- อนุมัติหรือปฏิเสธคำขอเข้า · เชิญออกจากกิลด์
- แต่งตั้ง/ปลดรองหัวหน้า · โอนตำแหน่งหัวหน้าให้สมาชิกคนอื่น
- รองหัวหน้าทำได้ทุกอย่างยกเว้น โอนหัวหน้า แต่งตั้งรองหัวหน้า และเชิญรองหัวหน้าคนอื่นออก
  (ใช้กติกาเดียวกับผู้ดูแลห้องก๊วนใน 0031 และบังคับในฐานข้อมูล ไม่ใช่แค่ซ่อนปุ่ม)
- หัวหน้าออกจากกิลด์ไม่ได้จนกว่าจะโอนตำแหน่ง ถ้าเหลือคนเดียว การออกคือการยุบกิลด์

### ตั้งค่าเริ่มต้น (แก้ได้ทุกข้อ)

| เรื่อง | ค่าเริ่มต้น | เหตุผล |
|---|---|---|
| สมาชิกสูงสุด | 30 คน | พอสำหรับก๊วนใหญ่ แต่ไม่ใหญ่จนอันดับกลายเป็นแข่งกันว่าใครคนเยอะ |
| ชื่อกิลด์ | 3–24 ตัวอักษร ห้ามซ้ำ (ไม่สนตัวพิมพ์เล็กใหญ่) | |
| แท็ก | 2–4 ตัว A–Z/0–9 หรือไทย ห้ามซ้ำ | แสดงหน้าชื่อในห้องก๊วน เช่น `[SNT] โดม` |
| ตรา | เลือกจากชุดไอคอน + สีที่ร้านเตรียม ~24 แบบ | ไม่ให้อัปโหลดรูปเอง เลี่ยงงานตรวจรูปและพื้นที่เก็บไฟล์ |
| คำอธิบาย | ไม่เกิน 200 ตัวอักษร | |
| ออกแล้วเข้ากิลด์ใหม่ได้เมื่อไหร่ | หลัง 3 วัน | กันการย้ายกิลด์ไปมาเพื่อปั่นอันดับปลายซีซั่น |
| สร้างกิลด์ | 1 ครั้งต่อคนต่อ 7 วัน | กันสร้างทิ้งรัว ๆ |
| คำขอเข้ากิลด์ | ค้างได้ทีละ 1 คำขอต่อคน ส่งได้ไม่เกิน 10 ครั้งต่อวัน | |

## XP และเลเวล

XP มาจาก **สิ่งที่เกิดขึ้นจริงที่ร้าน** เท่านั้น และนับให้กิลด์ที่ผู้เล่นสังกัด **ณ ตอนที่เกิดเหตุการณ์**
ไม่ย้อนหลัง ถ้าออกไปเข้ากิลด์อื่น XP ที่เคยทำให้ยังอยู่กับกิลด์เดิม

| เหตุการณ์ | XP | เงื่อนไข |
|---|---|---|
| ลงเล่น 1 เกมในห้องก๊วน | +10 | ทั้งห้องจัดอันดับและห้องชิล |
| ชนะ 1 เกม | +5 เพิ่ม | เฉพาะห้องจัดอันดับ |
| จองสนามและได้เล่นจริง | +20 ต่อชั่วโมง | ให้คนจอง การจองต้องยืนยันแล้ว ไม่ได้ค้างชำระ และเลยเวลาจบแล้ว |
| คืนรวมพล | +50 ต่อห้อง | ในห้องก๊วนเดียวกันมีสมาชิกกิลด์เดียวกันลงเล่นอย่างน้อย 4 คน |

กันการปั่น XP:

- ทุกห้องก๊วนผูกกับการจองสนาม (`party_rooms.booking_id`) และ XP นับเฉพาะห้องที่การจองยืนยันแล้ว
  การปั่นเกมจึงต้องเสียค่าสนามจริงอยู่แล้ว
- XP จากเกม (สองแถวแรก) นับได้ไม่เกิน **150 ต่อคนต่อวัน**
- ทุกเหตุการณ์บันทึกครั้งเดียว (มีคีย์ห้ามซ้ำ) ประมวลซ้ำก็ไม่ได้ XP เพิ่ม
- ถ้าการจองถูกยกเลิกหรือคืนเงินทีหลัง จะลง XP ติดลบหักคืน

**เลเวล** คิดจาก XP สะสมตลอดกาล (ไม่รีเซ็ต): เลเวล n ต้องมี XP สะสม `100 × n × (n − 1)`

| เลเวล | 1 | 2 | 3 | 4 | 5 | 10 | 20 |
|---|---|---|---|---|---|---|---|
| XP สะสม | 0 | 200 | 600 | 1,200 | 2,000 | 9,000 | 38,000 |

ประมาณการ: กิลด์ 8 คนที่มาเล่นสัปดาห์ละคืน คืนละ 6 เกมต่อคน และจอง 2 ชั่วโมง ได้ราว 650 XP ต่อสัปดาห์
คือขึ้นเลเวล 5 ในเดือนแรก และเลเวล 10 ราว 3–4 เดือน ตัวเลขจูนได้ทีหลังโดยไม่ต้องแก้โครงสร้าง

## ซีซั่น เหรียญรางวัล และอันดับ

- **ซีซั่นละ 1 เดือนตามปฏิทิน** (เวลาไทย) XP ซีซั่นคือผลรวม XP ที่เกิดในเดือนนั้น
- ตารางอันดับมี 3 แท็บ:
  - **XP ซีซั่นนี้:** ตัวหลักที่ใช้ให้รางวัล
  - **เลเวล:** XP สะสมตลอดกาล
  - **ฝีมือ:** ค่าเฉลี่ย Elo ของสมาชิก 4 คนที่แต้มสูงสุด ต้องมีสมาชิกที่เคยเล่นห้องจัดอันดับอย่างน้อย 4 คนถึงจะขึ้นแท็บนี้
- จบซีซั่น ระบบบันทึกผลถาวร และให้เหรียญ 🥇🥈🥉 กับ 3 อันดับแรกของแท็บ XP ซีซั่น
- **เหรียญความสำเร็จ** (ได้ครั้งเดียว ติดหน้ากิลด์ถาวร):
  - คืนรวมพลครั้งแรก
  - คืนรวมพลครบ 10 ครั้ง
  - ถึงเลเวล 5 / 10 / 20
  - สมาชิกครบ 10 คน
  - ชนะรวม 100 เกม

## ห้องก๊วนของกิลด์

- ตอนสร้างห้องก๊วน คนที่มีกิลด์ติ๊ก "ห้องของกิลด์" ได้ ห้องจะมีป้ายชื่อกิลด์ และขึ้นในหน้ากิลด์ส่วน "คืนก๊วนที่กำลังจะมา"
- **กติกาการเข้าห้องยังเหมือนเดิมทุกอย่าง** ห้องสาธารณะใครก็เข้าได้ ห้องส่วนตัวใช้รหัสเหมือนเดิม
  MVP ยังไม่มีห้องที่ "เฉพาะสมาชิกกิลด์"
- ในห้องก๊วนจะมีแท็กกิลด์นำหน้าชื่อผู้เล่นทุกคนที่มีกิลด์ ไม่ใช่เฉพาะห้องของกิลด์

## ความเป็นส่วนตัวและความปลอดภัย

- **ตารางสาธารณะไม่มี user id** ทำตามแบบแผน 0020/0030: กิลด์ใช้ `guild_id` ของตัวเอง
  สมาชิกแสดงด้วย `public_player_id` ชื่อ และรูปโปรไฟล์ แบบเดียวกับตารางอันดับผู้เล่น
- คนที่กด "ขอไม่แสดงชื่อ" ในตารางอันดับผู้เล่น จะแสดงในรายชื่อสมาชิกกิลด์เป็น "สมาชิก" ไม่มีชื่อและรูป
  แต่ยังนับ XP ให้กิลด์
- ออกจากกิลด์แล้วชื่อหายจากหน้ากิลด์ทันที ประวัติ XP แสดงเป็น "อดีตสมาชิก"
- **การเขียนทุกอย่างผ่านฟังก์ชันในฐานข้อมูล** (security definer) ที่ตรวจสิทธิ์และกติกาเอง
  ตารางจริงปิดการเขียนตรงด้วย RLS เหมือนห้องก๊วน
- ชื่อ แท็ก และคำอธิบาย ผ่าน `clean_party_text()` ตัวเดิม
- มีปุ่มรายงานกิลด์ ใช้คิวรายงานของคอมมูนิตี้ (เพิ่ม `'guild'` ใน `target_type`) แอดมินเปลี่ยนชื่อ ซ่อน หรือยุบกิลด์ได้
- แอดมินซ่อนหรือยุบกิลด์แล้ว **ไม่มีอะไรถูกลบจริง** เก็บไว้ตรวจย้อนหลังได้ แบบเดียวกับคอมมูนิตี้
- สวิตช์ `guild_settings.creation_open` ปิดการสร้างกิลด์ใหม่ชั่วคราวได้จากหน้าแอดมิน ไม่ต้อง deploy

## ไม่ทำในรอบนี้

- **เรื่องเงินทั้งหมด:** หารค่าสนาม กองกลางกิลด์ เหรียญแลกส่วนลด ค่าสมาชิกกิลด์
- ห้องก๊วนเฉพาะสมาชิกกิลด์ และการจองประจำในนามกิลด์
- นัดแข่งกิลด์ปะทะกิลด์ (ทำได้ในรอบถัดไปด้วยระบบจับคู่ที่มีอยู่)
- ภารกิจรายสัปดาห์
- แชทในเว็บ (ใส่ลิงก์ LINE OpenChat ของกิลด์ในคำอธิบายได้)
- อัปโหลดตราเอง
- แจ้งเตือน LINE หรือ Telegram ถึงสมาชิก

## โครงสร้างข้อมูล (ร่าง)

Migration ใหม่ไฟล์เดียว `0033_guilds.sql` (เลขจริงกำหนดตอนลงมือทำ ถ้ามี migration อื่นเข้ามาก่อน)
ไม่แก้ตารางการจองหรือการชำระเงิน
แก้ของเดิมแค่ 2 จุด คือเพิ่ม `party_rooms.guild_id` แบบ nullable และเพิ่ม `'guild'` ใน `community_reports.target_type`

```text
guild_settings        id=1, creation_open
guilds                id, name, name_key (lower, unique), tag (unique), emblem, color,
                      description, join_policy (open|approval|code), join_code,
                      status (active|hidden|disbanded), created_by, created_at
guild_members         guild_id, user_id, role (leader|officer|member),
                      joined_at, left_at, status (active|left|removed)
                      unique (user_id) where status = 'active'          -- one guild each
                      unique (guild_id) where role = 'leader' and active -- one leader
guild_join_requests   id, guild_id, user_id, status (pending|approved|rejected|withdrawn),
                      created_at, decided_by, decided_at
                      unique (user_id) where status = 'pending'
guild_xp_events       id, guild_id, user_id, source (match|win|court_hours|rally|reversal),
                      source_id, xp, created_at
                      unique (guild_id, source, source_id)   -- idempotent
guild_seasons         id, starts_on, ends_on, closed_at
guild_season_results  season_id, guild_id, xp, rank
guild_badges          guild_id, code, season_id null, earned_at

-- public mirrors (no user ids), synced by triggers like party_room_board
guild_board           guild_id, name, tag, emblem, color, description, join_policy,
                      member_count, level, total_xp, season_xp, skill_rating
guild_member_board    guild_id, player_key (public_player_id), name, avatar_url, role, joined_at
```

ฟังก์ชันหลัก (ทั้งหมด security definer และตรวจ `auth.uid()`):

- `create_guild`, `update_guild`, `disband_guild`
- `join_guild` (open หรือมีรหัส), `request_join_guild`, `decide_join_request`, `leave_guild`
- `kick_guild_member`, `set_guild_officer`, `transfer_guild_leader`, `new_guild_join_code`
- `can_create_guild(user)`: จุดเดียวสำหรับเงื่อนไขในอนาคต เช่น ผูกกับค่าสมาชิก แบบเดียวกับ `can_host_party()`
- `award_guild_xp_for_party(party_id)`: เรียกต่อจาก `record_party_result` ที่มีอยู่
- `award_guild_xp_for_booking(booking_id)`: เรียกจาก pg_cron ทุกชั่วโมง สำหรับการจองที่เลยเวลาจบแล้ว
- `close_guild_season()`: pg_cron วันที่ 1 ของเดือน 00:05 เวลาไทย

ตัวเลขทุกตัว (XP ต่อเหตุการณ์ เพดานรายวัน สูตรเลเวล) อยู่ในฟังก์ชันเดียว `guild_xp_rules()`
และมีสำเนาใน `src/lib/guilds/rules.ts` พร้อมเทสต์ที่เช็กว่าสองที่ตรงกัน
แบบเดียวกับที่ `src/lib/config.ts` ต้องตรงกับราคาในฐานข้อมูล

  - XP ตรงตามตาราง และไม่เกินเพดานรายวัน
  - ย้ายกิลด์แล้ว XP ไม่ตามไป
  - ประมวลซ้ำไม่ได้ XP เพิ่ม
  - ปิดซีซั่นแล้วได้อันดับและเหรียญถูกต้อง
  - ตารางสาธารณะไม่มีคีย์ไหนตรงกับ `auth.users.id`
- `scripts/test-db.mjs`: เพิ่มเคสสิทธิ์
  - รองหัวหน้าโอนหัวหน้าไม่ได้
  - คนนอกเชิญคนออกไม่ได้
  - เข้า 2 กิลด์พร้อมกันไม่ได้
  - หัวหน้าออกโดยไม่โอนไม่ได้
- Unit test ใน `test/guilds.test.ts`: สูตรเลเวล แถบ XP และการแสดงผล
- หน้า `/sandbox/guilds`: ดูหน้าจอที่ 390px ทั้งโหมดสว่างและมืด ก่อนต่อข้อมูลจริง

## แบ่งงานเป็นช่วง

1. **ฐานข้อมูล + sandbox:** `0033_guilds.sql` และเคสทดสอบทั้งหมด ยังไม่มีหน้าเว็บ
2. **หน้าเว็บ:**
   - `/guilds`, `/guilds/[id]`, `/guilds/new`
   - การ์ดใน `/me`
   - แท็กกิลด์ในห้องก๊วน
   - ติ๊ก "ห้องของกิลด์"
3. **XP ซีซั่น เหรียญรางวัล:** ต่อ XP เข้ากับผลเกมและการจอง ตั้ง pg_cron ปิดซีซั่น
4. **แอดมินและเปิดใช้:** `/admin/guilds` คิวรายงาน สวิตช์เปิดรับ แล้วโดมรัน migration บนฐานข้อมูลจริง

แต่ละช่วงเป็น PR แยก ช่วง 1 ต้องให้โดมอนุมัติก่อน เพราะเป็น migration

## คำถามที่ต้องการคำตอบจากโดม

1. **หนึ่งคนหนึ่งกิลด์** โอเคไหม หรืออยากให้อยู่ได้หลายกิลด์ (หลายกิลด์ทำให้อันดับปั่นง่ายขึ้นมาก)
2. **ใครสร้างกิลด์ได้:**
   - ทุกคนที่ล็อกอิน
   - หรือต้องเคยจองหรือเล่นห้องก๊วนที่ร้านอย่างน้อยกี่ครั้ง
3. **ซีซั่นละ 1 เดือน** หรือ 3 เดือน
4. **เกี่ยวกับค่าสมาชิก ฿59/เดือน** ในเอกสารห้องก๊วนที่ยังเปิดอยู่:
   - แยกกันไปก่อน ซึ่งเป็นค่าที่เสนอในเอกสารนี้
   - หรืออยากให้ค่าสมาชิกเป็นสิทธิ์สร้างกิลด์ในอนาคต (ทำได้ผ่าน `can_create_guild()` โดยไม่ต้องแก้โครง)
5. **หน้ากิลด์ให้คนที่ไม่ล็อกอินเห็นด้วย** ไหม (ค่าเริ่มต้นคือต้องล็อกอิน เหมือนตารางอันดับผู้เล่น)
6. **ตัวเลข XP และสมาชิกสูงสุด 30 คน** โอเคไหม
