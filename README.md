# ระบบจองสนามแบดมินตัน 🏸

จองสนาม 4 สนาม (฿130/ชม. เปิดทุกวัน 09:00–23:00) · เช็คคิวว่างแบบเรียลไทม์ · ชำระเงินด้วย PromptPay QR + แนบสลิป · แอดมินตรวจสลิป

**Stack:** Next.js 15 (App Router) + Supabase (Postgres, Realtime, Auth, Storage)

## ลำดับการใช้งาน

1. ลูกค้าเปิดหน้าแรก เห็นตาราง 4 สนาม × 09:00–23:00 ที่อัปเดตเองทันทีเมื่อมีคนจอง (Supabase Realtime)
2. เลือกช่องว่างและจำนวนชั่วโมง (1–4) แล้วกดจอง ระบบล็อกคิวไว้ **15 นาที** (สถานะ `pending_payment`)
3. หน้าชำระเงินสร้าง **PromptPay QR พร้อมยอดเงิน** ลูกค้าสแกนโอน แล้วอัปโหลดสลิป สถานะเป็น `awaiting_review`
4. ยอดชำระเป็นราคาเต็ม (เช่น ฿130) ไม่มีเศษสตางค์ แอดมินตรวจสลิป หรือเปิด EasySlip ให้ตรวจอัตโนมัติ ถ้าตั้งมือถือร้านส่งแจ้งเตือนเงินเข้ามา แอดมินจะเห็นเงินเข้าในหน้า `/admin` ไว้เทียบกับสลิป
5. สลิปที่ระบบตรวจไม่ผ่าน (ยอดไม่ตรง, ผู้รับไม่ตรง, สลิปซ้ำ, อ่านไม่ได้, API ล่ม) จะ**ไม่ถูกปฏิเสธอัตโนมัติ** แต่จะไปรอแอดมินที่ `/admin` พร้อมเหตุผล แอดมินกดยืนยัน หรือปฏิเสธเพื่อให้ลูกค้าอัปโหลดใหม่ภายใน 15 นาที (ส่งได้สูงสุด 3 ครั้งต่อการจอง)
6. ถ้าไม่ชำระภายในเวลา ระบบปล่อยคิวเอง (`expired`)
7. **ลูกค้าที่จองทางโทรศัพท์ / LINE / หน้าร้าน:** แอดมินบันทึกในหน้า `/admin` (ชื่อ, เบอร์, หมายเหตุ) การจองยืนยันทันทีและขึ้นบนตารางเรียลไทม์ ลูกค้าออนไลน์จึงจองทับไม่ได้ จ่ายที่หน้าร้าน

## กฎที่บังคับใน database (ไม่ใช่แค่หน้าเว็บ)

- **ห้ามจองซ้อน:** ใช้ exclusion constraint บน `(court_id, tstzrange)` จึงกันได้แม้มีคนกดจองพร้อมกัน
- ราคาคำนวณฝั่ง server จาก `courts.price_per_hour` ไคลเอนต์ส่งราคามาเองไม่ได้
- 1 คนจองได้ไม่เกิน 6 ครั้งต่อชั่วโมง และมีการจองที่ยังไม่ยืนยันได้ไม่เกิน 3 รายการ
- สลิปหนึ่งใบ (`transRef`) ใช้ได้กับการจองเดียว และ database ไม่ยอมยืนยันอัตโนมัติถ้ายอดในสลิปไม่ตรงกับยอดจอง
- ต้องเริ่มตรงชั่วโมง อยู่ในเวลาเปิด จองล่วงหน้าได้ไม่เกิน 14 วัน และค้างชำระได้ไม่เกิน 2 รายการต่อคน
- สลิปต้องอยู่ในโฟลเดอร์ของผู้ใช้เองและมีไฟล์อยู่จริงใน Storage
- ผู้ใช้แก้ `is_admin` ของตัวเองไม่ได้ และอ่านได้เฉพาะการจองของตัวเอง
- ตารางสาธารณะ `court_occupancy` ไม่มีข้อมูลส่วนตัว ใช้สำหรับแสดงคิวเรียลไทม์

เวลาเปิด-ปิดอยู่ 2 ที่ ต้องแก้ให้ตรงกัน: `src/lib/config.ts` และฟังก์ชัน `opening_hours_ok()` ใน migration 0001 ส่วนกฎอื่น เช่น จำนวนชั่วโมงสูงสุดหรือเวลาล็อกคิว อยู่ใน `create_booking()`

## ติดตั้ง

1. สร้างโปรเจกต์ที่ [supabase.com](https://supabase.com)
2. เปิด SQL Editor แล้วรันไฟล์ใน `supabase/migrations/` ตามลำดับ 0001 → 0007 (เปิด extension **pg_cron** ก่อนรัน 0002)
   (ถ้าใช้ Supabase CLI: `supabase db push`)
   ตอนขึ้นเว็บจริง: รัน `supabase/ops/keep-warm.sql` (แก้ URL ให้ตรงโดเมน) ให้ระบบยิงเว็บทุก 5 นาที กันเซิร์ฟเวอร์หลับ
3. Authentication → URL Configuration: เพิ่ม `http://localhost:3000/auth/callback` (และโดเมนจริงตอนขึ้นระบบ) ใน Redirect URLs
   แนะนำ: Authentication → Email Templates → Magic Link เปลี่ยนลิงก์เป็น
   `{{ .RedirectTo }}&token_hash={{ .TokenHash }}&type=email`
   เพื่อให้กดลิงก์จากแอป LINE/Gmail หรือคนละเบราว์เซอร์ได้ (ค่าเริ่มต้นแบบ PKCE ใช้ได้เฉพาะเบราว์เซอร์ที่กดขอลิงก์)
4. ตั้งค่า env:
   ```bash
   cp .env.example .env.local
   ```
   ใส่ `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` และ `PROMPTPAY_ID` (เบอร์มือถือหรือเลขบัตรประชาชนที่ผูกพร้อมเพย์ของร้าน)
5. รัน:
   ```bash
   npm install
   npm run dev
   ```
6. ตั้งแอดมิน: เข้าสู่ระบบด้วยอีเมลของแอดมินหนึ่งครั้ง แล้วรันใน SQL Editor
   ```sql
   update public.profiles set is_admin = true
   where id = (select id from auth.users where email = 'admin@example.com');
   ```

แก้ชื่อหรือราคาสนามได้ที่ตาราง `public.courts`

### เข้าสู่ระบบด้วย LINE และแจ้งเตือนร้านทาง LINE

**LINE Login** (ไม่ต้องมี LINE OA ก็ใช้ได้)
1. ไปที่ [LINE Developers Console](https://developers.line.biz/console/) สร้าง Provider ของร้าน แล้วสร้าง channel แบบ **LINE Login** (App type: Web app)
2. ตั้ง Callback URL เป็น `https://<โดเมนของคุณ>/auth/line/callback`
3. ใส่ `LINE_LOGIN_CHANNEL_ID`, `LINE_LOGIN_CHANNEL_SECRET` และ `SUPABASE_SERVICE_ROLE_KEY` ใน `.env.local` แล้วรัน migration `0006_line.sql`
4. หน้าเข้าสู่ระบบจะมีปุ่ม "เข้าสู่ระบบด้วย LINE" ส่วนอีเมลยังใช้ได้เป็นทางสำรอง

**แจ้งเตือนร้านทาง LINE** (ต้องมี LINE OA) LINE Notify ปิดบริการไปแล้วเมื่อ 31 มี.ค. 2025 จึงใช้ Messaging API ของ LINE OA ร้านแทน
1. สร้าง LINE OA ของร้าน (ฟรี) แล้วเปิด Messaging API ภายใต้ **Provider เดียวกับ LINE Login** (ถ้าคนละ Provider ระบบจะส่งหาแอดมินไม่ได้ เพราะ user ID ไม่ตรงกัน)
2. ออก Channel access token (long-lived) แล้วใส่เป็น `LINE_MESSAGING_TOKEN`
3. ให้แอดมินแต่ละคน**เข้าสู่ระบบด้วย LINE** 1 ครั้ง และเพิ่ม LINE OA ของร้านเป็นเพื่อน จากนั้นตั้งสิทธิ์แอดมินให้บัญชีนั้น
   ```sql
   update public.profiles set is_admin = true
   where line_user_id is not null and display_name = 'ชื่อ LINE ของแอดมิน';
   ```
4. ระบบจะส่งข้อความหาแอดมินเมื่อ: ยืนยันการจองอัตโนมัติ (`confirmed`), มีสลิปรอตรวจ (`needs_review`), มีเงินเข้าที่จับคู่ไม่ได้ (`unmatched`) เลือกได้ด้วย `LINE_NOTIFY_EVENTS`
   - LINE OA แพ็กเกจฟรีส่งข้อความได้จำนวนจำกัดต่อเดือน ถ้าข้อความเยอะเกิน ให้ตัด `confirmed` ออกก่อน เพราะหน้าแอดมินแสดงการจองแบบเรียลไทม์อยู่แล้ว
5. ใส่ลิงก์หน้าจอง `https://<โดเมนของคุณ>/` ไว้ใน Rich Menu ของ LINE OA ลูกค้าจะกดจองจากแชทร้านได้เลย

### แจ้งเตือนเงินเข้าจากมือถือร้าน (ไม่บังคับ ไม่มีค่าบริการ)

ใช้มือถือ Android ของร้านที่ติดแอปธนาคารไว้ ส่งต่อการแจ้งเตือน "เงินเข้า" มาที่ระบบ เงินเข้าแต่ละรายการจะขึ้นที่ `/admin` (และแจ้งใน LINE) พร้อมการจองที่รอชำระยอดเดียวกัน แอดมินเทียบกับสลิปได้โดยไม่ต้องเปิดแอปธนาคาร

ระบบ**ไม่ยืนยันการจองจากแจ้งเตือนเอง** เพราะทุกการจองราคาเท่ากัน (เช่น ฿130) ยอดเงินอย่างเดียวบอกไม่ได้ว่าเป็นของใคร อาจเป็นลูกค้าหน้าร้านที่สแกนจ่ายก็ได้

**ฝั่งเซิร์ฟเวอร์** (`.env.local`)
- `SUPABASE_SERVICE_ROLE_KEY`
- `BANK_WEBHOOK_SECRET` ค่าสุ่มยาว 32 ตัวขึ้นไป สร้างได้ด้วย
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
  **ใครได้ค่านี้ไปจะส่งรายการเงินเข้าปลอมเข้ามาได้** เก็บไว้แค่ในเซิร์ฟเวอร์กับมือถือร้าน ถ้ามือถือหายให้เปลี่ยนค่าใหม่ทันที
- `BANK_APP_PACKAGES` ชื่อแพ็กเกจของแอปธนาคารบนมือถือร้าน คั่นด้วย `,` เช่น K PLUS = `com.kasikorn.retail.mbanking.wap`, SCB EASY = `com.scb.phone` (ดูได้จาก `id=` ใน URL หน้าแอปบน Play Store) ระบบจะไม่นับแจ้งเตือนจากแอปอื่นเลย ข้อความ "เงินเข้า 130.00" ที่มาจาก LINE จึงไม่ถูกนับ
- รัน migration `0004_bank_notifications.sql` และ `0007_round_amounts.sql`

**ฝั่งมือถือร้าน** (Android + แอป [MacroDroid](https://www.macrodroid.com))
1. ในแอปธนาคาร เปิดการแจ้งเตือนเงินเข้า และให้ MacroDroid มีสิทธิ์อ่านการแจ้งเตือน (Notification Access)
2. ปิด battery optimization ของ MacroDroid เสียบชาร์จ และต่อเน็ตไว้ตลอด
3. สร้าง Macro "ส่งแจ้งเตือนเงินเข้า"
   - Trigger: **Notification → Notification Received** → เลือกแอปธนาคารของร้าน
   - Action: **HTTP Request**
     - Method `POST`, URL `https://<โดเมนของคุณ>/api/bank-notifications`
     - Header Params: `Authorization` = `Bearer <BANK_WEBHOOK_SECRET>`
     - Content Body: เลือก `text/plain` แล้วใส่ 4 บรรทัดนี้ตามลำดับ
       ```
       {not_app_package}
       {not_timestamp}
       {not_title}
       {notification}
       ```
4. สร้าง Macro "heartbeat": Trigger **Regular Interval ทุก 30 นาที** → HTTP Request แบบเดียวกัน แต่ Content Body เป็นคำว่า `heartbeat` หน้าแอดมินจะเตือนเมื่อมือถือเงียบไปเกิน 75 นาที
5. ทดสอบ: โอนเงินมีเศษสตางค์ (เช่น ฿1.23) เข้าบัญชีร้าน เพื่อเช็คว่าระบบอ่านทศนิยมได้ รายการต้องขึ้นที่ `/admin` ในหัวข้อ "เงินเข้า" พร้อมยอดที่ถูกต้อง ถ้าขึ้นว่า "ไม่ทราบยอด" ให้คัดลอกข้อความแจ้งเตือนนั้นมาปรับตัวอ่านใน `src/lib/bank/notification.ts` แล้วเพิ่มเป็นเคสใน `test/bank-notification.test.ts`

**กฎการรับแจ้งเตือน**
- ต้องมาจากแอปธนาคารที่อนุญาต และเป็นรายการ "เงินเข้า" ที่อ่านยอด 2 ตำแหน่งได้ชัด ถ้ากำกวมระบบจะไม่เดา
- การจองที่แนะนำต้องเป็นการจองออนไลน์ที่ยังรอชำระหรือรอตรวจสลิป ยอดเท่ากัน และสร้างก่อนเวลาโอน
- แจ้งเตือนซ้ำนับครั้งเดียว
- ตรวจแล้วกด "จัดการแล้ว" รายการจะหายจากหน้าแอดมิน

### เปิดตรวจสลิปอัตโนมัติ (EasySlip, ไม่บังคับ)

ถ้าไม่ตั้งค่าส่วนนี้ ระบบยังใช้งานได้ แต่แอดมินต้องตรวจสลิปเองทุกใบ

1. สมัครและสร้าง API key ที่ [developer.easyslip.com](https://developer.easyslip.com)
2. ใส่ใน `.env.local` (เป็นค่าฝั่ง server ทั้งหมด ห้ามขึ้นต้นด้วย `NEXT_PUBLIC_`)
   - `EASYSLIP_API_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (Supabase → Settings → API) ใช้บันทึกผลตรวจ
   - `SLIP_RECEIVER_NAME` ชื่อบัญชีรับเงินตามที่ขึ้นในสลิป ใส่ชื่อ-นามสกุลเต็ม ได้ทั้งไทยและอังกฤษ คั่นด้วย `,` (อย่าใส่แค่ชื่อต้น) **ถ้าไม่ใส่ ระบบจะไม่ยืนยันอัตโนมัติ**
   - `SLIP_RECEIVER_BANK_ACCOUNT` เลขบัญชีธนาคารที่ผูกพร้อมเพย์ (สลิปบางธนาคารแสดงแค่เลขบัญชี ไม่แสดงเบอร์พร้อมเพย์)
3. ทดลองจองแล้วโอนจริง 1 ครั้ง เพื่อเช็คว่ารูปแบบชื่อและเลขบัญชีในสลิปของธนาคารร้านตรงกับที่ตั้งค่าไว้

กฎการยืนยันอัตโนมัติ (`src/lib/slip/evaluate.ts`) มีดังนี้ ถ้าไม่ผ่านข้อใดข้อหนึ่ง สลิปจะไปรอแอดมิน
- ยอดในสลิปต้องตรงกับยอดจอง
- เลขพร้อมเพย์หรือเลขบัญชีผู้รับต้องตรง เห็นอย่างน้อย 4 หลักและความยาวต้องเท่ากัน และชื่อผู้รับต้องตรง
- เวลาโอนต้องไม่ก่อนเวลาจอง (เผื่อ 5 นาที)
- `transRef` ต้องไม่เคยใช้กับการจองอื่น
